# 開発の手引き

ツールを直したり、新しいツールを足したりする人向けの説明です。使い方は [README](../README.md) を見てください。

## 決まりごと

- HTML・CSS・JavaScript だけで作ります。ビルド作業はありません。ファイルを直して `main` に入れれば、GitHub Pages にそのまま出ます
- 外部ライブラリは CDN を使わず、`shared/vendor/` に同梱します（学校のネットワークで CDN がブロックされることがあるため）
- ファイルはどこにも送信せず、ブラウザの中だけで処理します
- 一度開いたツールは、ネットワークがなくても動くようにします
- 見た目は「Chromebookアプリ風」でそろえます。丸いアイコン（ツールの色の丸に白い線の絵）、上のバーに丸い戻るボタンとツール名、丸みのあるボタン。画面には絵文字を使わず、線のアイコン（各 `index.html` の `<svg class="sprite">` の中の `<symbol>`）を使います。フォントは端末のものだけを使います
- タッチ画面（タブレットモード）でも使えるように、ドラッグは HTML のドラッグ＆ドロップではなく pointer イベントで作ります
- 一度公開したあとは、保存の名前（localStorage のキー）と保存の形を変えません。変えると、使っている人の設定や記録が消えます。PDF→画像とPDF結合・分割・回転の設定は JSON ではなく文字列のまま保存しているので、そのままにします

## フォルダの構成

| 場所 | 中身 |
| --- | --- |
| `index.html` | トップページ（ツールを選ぶ入り口） |
| `sw.js` | サイト全体のサービスワーカー（オフライン用の保存） |
| `<ツール名>/` | ツール1つ分。`index.html`・`style.css`・`app.js`・`icon.svg`・`manifest.webmanifest` |
| `<ツール名>/sw.js` | 古い版のサービスワーカーを外すためだけのファイル。2027年2月以降に消してよい |
| `_template/` | 新しいツールのひな形 |
| `shared/css/base.css` | どのツールでも同じ見た目（上のバー・ボタン・アイコン・メッセージ） |
| `shared/js/` | どのツールでも使う部品（下の一覧） |
| `shared/vendor/` | 同梱ライブラリ。一覧と入手元・ライセンスは [`shared/vendor/README.md`](../shared/vendor/README.md) |
| `tests/` | 自動の動作確認。説明は [`tests/README.md`](../tests/README.md) |
| `docs/` | この手引き |

### 共通部品（`shared/js/`）

新しいツールでも、同じことをするときはこれを使ってください。

| ファイル | できること |
| --- | --- |
| `offline.js` | `registerOffline([...])`: そのツールのファイルをオフライン用に保存する。どのツールも `app.js` の最後で呼ぶ |
| `status.js` | `showStatus(文, { error, sticky, ms })` / `hideStatus()`: 画面下のメッセージ（`<div id="status">`） |
| `files.js` | `download(blob, 名前)`: ファイルを保存。`onFileDrop(関数)`: ファイルのドラッグ＆ドロップ（`<div id="drop-overlay">`）。`isPdf`・`baseName` |
| `storage.js` | `loadJson` / `saveJson` / `loadText` / `saveText`: 設定の保存。保存できない環境でも止まらない |
| `pdf.js` | `openPdf(データ, { name })`: pdf.js でPDFを開く。パスワードが必要なPDFは `password.js` の画面で聞く（やめたときは `PasswordException`）。`rasterizePdf(pdf)`: 保護されたPDFをページの画像から作り直す |
| `pdf-lib.js` | `loadPdfLib()` / `loadFontkit()`: pdf-lib と fontkit を、保存などで必要になったときに読み込む |
| `font-jp.js` | `subsetFont(文字)`: PDFに書き込む日本語フォントを、使う文字だけに縮めて返す |
| `zip.js` / `unzip.js` | ZIPの作成と読み取り |
| `lazy.js` | 画面の近くのものだけ描き、遠くのものの絵を手放す（長いPDFでメモリを使いすぎないため） |
| `page-viewer.js` | 拡大・縮小できるPDFのページの列（PDF文字入れ・手書き・署名・一括採点） |
| `ink.js` / `history.js` | ページへの手書き・ハンコ・選択と移動と、「元に戻す」の記録（手書き・署名と一括採点） |

`shared/` に新しいファイルを足したときは、`shared/js/offline.js` の `SHARED` の一覧にも書き足してください。書き忘れると、そのファイルがオフライン用に保存されず、ネットワークのない所で開けなくなります（自動の動作確認で気づけます）。

pdf-lib は `<script>` で読み込まず、使う直前に `const { PDFDocument } = await loadPdfLib();` のようにして使います。

## 新しいツールの足し方

1. `_template/` をフォルダごとコピーして、名前を変える（例: `timer/`）。フォルダ名は英小文字とハイフンにします
2. ツールの色を決めて、`style.css` の `--accent` と `--accent-dark`、`icon.svg` の丸の色、`manifest.webmanifest` の `theme_color`、`index.html` の `theme-color` を同じ色にする
3. `index.html`・`manifest.webmanifest` のツール名と説明、`icon.svg` の白い線の絵を書きかえる
4. `app.js` の保存の名前（`SETTINGS_KEY`）をツールに合わせて変え、中身を作る。テスト用の `window.__newTool` も名前を合わせる
5. ほかのファイル（画像やライブラリ）を使うときは、`app.js` の最後の `registerOffline([...])` の一覧に足す
6. トップページ（ルートの `index.html`）の、合うグループ（「PDF」か「そのほかのツール」）の `<ul class="apps">` に `<li>` を1つ足す
7. README のツール一覧の表に1行と、使い方の節を足す
8. `tests/smoke.cjs` の `TOOLS` に、そのツールの確認を足す（`_template` の確認が最小の例です）

## ライブラリを新しい版にする

`shared/vendor/` のフォルダ名には版が入っていて、中身は書きかえません。

1. 新しい版のフォルダを作る（例: `shared/vendor/pdfjs-5.0.0/`）。ライセンスのファイルも入れる
2. 古いフォルダ名を使っている所を探して、すべて新しいフォルダ名に直す

   ```sh
   grep -rn "pdfjs-4.10.38" --include=*.js --include=*.html . | grep -v shared/vendor/
   ```

   見つかるのは、`shared/js/` の部品（`pdf.js`・`pdf-lib.js`・`font-jp.js`）、各ツールの `registerOffline([...])` の一覧、PDF文字取り出しの OCR（`pdf-extract/app.js`）などです
3. `shared/vendor/README.md` の表を直す
4. 自動の動作確認を通してから、古いフォルダを消す

サービスワーカー（`sw.js`）の番号（`itc-v1`）は上げなくて大丈夫です。ライブラリはフォルダ名ごとに保存されるので、フォルダ名が変われば新しい版が読み込まれます。古い版のファイルはブラウザに残ったままになるので、フォントや OCR のデータのような大きなものを入れかえたときだけ、`itc-v2` のように上げると古い保存がまとめて消えます（次に開いたときに全部を読み込み直します）。

ツール自身のファイル（`app.js` など）は、ネットワークがあるときは毎回新しいものを読むので、直したときに何かを上げる必要はありません。

## 動作の確認

コードを直したら、自動の動作確認を通してください。Node.js 22 以上と Playwright が必要です。

```sh
node tests/smoke.cjs              # 全ツールを開いて、操作・保存・オフラインを確かめる
node tests/smoke.cjs pdf-text     # 1つのツールだけ
node tests/migration.cjs          # 古い版を使っていたブラウザが新しい版に移れるか
```

ほかのオプション（OCR、狭い画面、CSS の比較など）は [`tests/README.md`](../tests/README.md) にあります。

URL の最後に `?debug` を付けると（例: `pdf-sign/?debug`）、「元に戻す」の記録が書きかえられないように固められ、記録を直接書きかえてしまう間違いがあるとエラーになります。PDFに手書き・署名とPDF一括採点の確認はこの状態で行います。

## 消してよいもの

- 各ツールのフォルダにある `sw.js`（ルートの `sw.js` ではありません）: 2027年2月以降に消してかまいません。消すときは、ルートの `sw.js` の `LEGACY` と `shared/js/offline.js` の古いサービスワーカーを外す処理も、あわせて消せます
